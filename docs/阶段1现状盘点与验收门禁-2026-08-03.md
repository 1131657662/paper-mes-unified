# 阶段 1 现状盘点与验收门禁（2026-08-03）

## 当前状态

阶段 1 已完成只读现状盘点，并在代码分支关闭普通工序新增、链式工序普通修改/删除、已下发计划普通卷号维护和未确认打印直接完成加工四个绕过入口；阶段 1 代码尚未部署生产，也未执行阶段 1 数据库迁移。阶段 0 已完成生产切换并关闭；V1 至 V3.49 历史 fixture 仍未取得，只能继续声明该历史迁移链“未验证”。

阶段 1 目标是关闭工艺与计划完整性缺口：计划冻结、版本化重新下发、链式血缘、明确业务命令、历史字段只读兼容，以及孤儿/跨单/软删除约束。不得借阶段 1 回填虚构历史事件或删除无法解释的存量数据。

## 已具备的基础

- `ProcessRoutePreviewer` 已校验阶段正数、连续编号、紧邻上一阶段输入、重复输入、重复消费、重复产出键和产出尺寸/重量边界。
- `ProcessRouteSaveService` 只允许待下发状态重建路线；`ProcessRouteAppendService` 也只允许待下发状态追加，已下发计划不能直接追加链式工艺。
- 普通工序新增策略已移除待回录附加工艺例外；草稿只能维护附加工艺，待下发可维护计划，已下发后不能再经普通工序入口新增、修改或删除工艺。
- 加工单、原纸和成品的通用状态 HTTP 入口均返回 405；成品报废已有独立权限、原因、占用校验、审计和库存流水命令。
- 下发后变更已有 `order:manage` 权限、原因、乐观版本、前后 `snap_print`、版本号、操作者、时间和重新下发日志基础。
- 多母卷阶段产出被消费时保留 `FinishOriginalRel`，不会再删除其他来源血缘。
- 新机台写入只接受 `MACHINE`，历史 `WORKSTATION` 只读；前端已隐藏班组录入和展示；仓库页面使用“仓库地址/说明”；登录页范围外宣传文案已移除。

## 当前阻断项

1. 已关闭：`updateProcessStep` 和 `deleteProcessStep` 在任何写入前同时检查工序自身链式拓扑、阶段产出、阶段输入/来源和子工序引用；命中任一活动关系即拒绝普通修改或删除，只允许后续受控路线变更命令处理。
2. 已关闭：普通工序入口和 `FinishRollServiceImpl` 普通卷号命令均只允许待下发状态；加工中、待回录及以后状态只能通过重新下发或回录命令维护正式/备用成品。
3. 已关闭：`completeProcessing` 在统一状态流转入口要求 `print_count > 0`；详情页和列表页也会禁用未确认打印单据的“转待回录”。`print_count` 由用户在纸张输出后执行“确认已完成打印”时递增，属于人工确认记录，不代表打印机设备回执。生产中现有 2 张加工中且 `print_count=0` 的单据在部署后会被门禁拦截，必须先核对实物并完成打印确认。
4. 已关闭：`ProcessOrderCreateDTO` 和 `DraftOrderBaseDTO` 已移除 `teamGroup` 写入属性；`BeanUtils.copyProperties` 不再有该属性可复制。`ProcessOrder.teamGroup` 实体字段保留用于历史值只读读取，新请求携带旧 `team_group` 字段不会写入。
5. `biz_process_order_issue_version` 的 PENDING 行会原地更新为 APPLIED/ARCHIVED；数据库没有触发器限制终态修改或删除。重新下发命令也没有 request-id/payload-hash 幂等契约，网络重试只能依靠版本冲突报错。
6. 39 张历史 `snap_print` 没有版本行；当前版本列表无法完整解释“V3.53 前已有快照”的来源边界。
7. 工艺阶段、参数和成品血缘主要依靠应用校验，缺少足够的数据库 `RESTRICT` FK 和跨单一致性约束；`biz_finish_original_rel` 缺少活动 `(finish_uuid, original_uuid)` 唯一约束。
8. `biz_process_config_draft`、`sys_dict_item`、`sys_config_item` 和 `sys_no_rule` 仍使用 `(业务键, is_deleted)` 唯一键。当前尚未触发冲突，但“删除、重建、再次删除”会产生结构性冲突；16 条已删除草稿意味着该路径必须在后续重复生命周期前修正。
9. 仓库 UI 已改为“地址/说明”，但库存导出仍使用“仓库位置”等旧文案，类型和实体注释仍保留“库位/地址”，范围语义尚未完全统一。

## 实施顺序

1. 已固化只读数据巡检 SQL 和测试 fixture，并用生产只读复跑锁定上述计数；后续每次约束迁移前必须重跑，任何非零孤儿/跨单/重复血缘必须先出具清单，不直接删除。
2. 定义计划冻结边界：待下发可编辑；加工中、待回录及以后状态只能通过带原因、expectedVersion、requestId 和 payload hash 的重新下发命令变更计划。
3. 已完成普通工序和卷号接口绕过路径收口；链式工序只能由路线命令整体重建，实际生产偏差另走回录/异常命令。
4. 完成下发版本终态不可变、重发幂等和历史 `LEGACY_UNVERSIONED` 读取策略，再处理 39 张存量快照；不得填造操作者或发生时间。
5. 在零异常 preflight 后前滚增加活动血缘唯一约束、必要的 `RESTRICT` FK 和安全软删除键；迁移失败不得登记 `applied`。
6. 已完成 `team_group` 后端写入收口和打印完成门禁；仓库文案仍需完成 API/UI/导出一致性测试。

## 阶段 1 验收门禁

以下任一项失败均不得发布阶段 1：

1. 路线阶段号不连续、输入不是紧邻上段、重复消费、跨单引用、非正数尺寸/数量/重量或无最终产出时，后端必须返回明确 4xx，且事务零写入。
2. 已下发计划的普通工序、链式路线、正式成品计划和卷号变更全部被拒；重新下发必须校验 `order:manage`、原因、expectedVersion、requestId、payload hash，并保证同请求幂等、不同 payload 冲突。
3. 每次重新下发保留旧快照、新快照、版本号、操作者、变更时间、下发时间和操作日志；APPLIED/ARCHIVED 终态不得 UPDATE/DELETE。历史快照必须标为未版本化存量，不伪造事件元数据。
4. 加工完成前必须存在至少一次人工确认打印记录；UI 和审计文案必须明确该记录不代表打印机设备回执。未确认打印时，详情页和列表页均不得发起正式完成加工命令。
5. 原纸、成品和加工单通用状态入口继续为 405；报废只能走 `inventory:scrap` 专用命令，并保持库存投影与账本同事务一致。
6. 新请求不能写入 `WORKSTATION` 或 `team_group`；历史值只读。仓库 `location` 只能表述为地址/识别说明，不建立库位层级语义。
7. 生产 preflight 的孤儿、跨单、重复活动血缘和软删除冲突清单为 0；迁移后 FK、唯一约束、checksum 和 schema diff 门禁通过。
8. 后端服务/集成/迁移契约全量测试、前端测试、lint、生产构建和 1366/1440/1920 登录态核心流程通过；版本变更需覆盖并发、重试、回滚和旧数据只读场景。

## 回滚边界

- 新约束和审计结构只允许前滚，不删除历史版本、快照、血缘或操作日志。
- 可通过关闭新命令入口回退应用读取，但不得重新开放通用状态或下发后直接编辑。
- 数据约束发布前必须保留生产备份和只读 preflight 证据；发现存量异常时暂停迁移并由业务确认修复清单。
- 阶段 1 不改变阶段 0 开账流水，也不补造切换日前库存事件。
